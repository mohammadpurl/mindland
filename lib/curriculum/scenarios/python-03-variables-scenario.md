## ۱. چارچوب نقش‌ها

| نقش | کیست | کار او چیست |

| **مینی** | همون کاراکتر | حالا می‌تونه یه چیزی رو یه‌بار توی یه «جعبه» بذاره و هر وقت خواستی، بدون این‌که دوباره بنویسیش، نگاش کنه |
| **دانش‌آموز** | کارگردان | باید یاد بگیره به‌جای تکرار دستی یه مقدار، یه بار توی یه جعبه‌ی اسم‌دار بذارتش |

## ۲. هدف قابل‌اندازه‌گیری

در پایان جلسه، دانش‌آموز می‌تواند:
- یک مقدار را در یک متغیر ذخیره کند و آن را در چند جای مختلف کد دوباره استفاده کند.
- مقدار یک متغیر را وسط برنامه تغییر دهد و ببیند چاپ بعدی همان تغییر را نشان می‌دهد.
- توضیح دهد که وقتی اسم یک جعبه‌ی تعریف‌نشده را صدا بزنی، مینی نمی‌داند کدام جعبه را می‌گویی.

## ۳. استعاره ثابت درس

**«به‌جای این‌که هربار دوباره بگی، یه بار بذارش تو جعبه.»**
اگه بخوای اسمت رو ۳ بار توی برنامه بیاری، باید هر بار دوباره تایپش کنی — و اگه بخوای عوضش کنی، باید همه‌ی جاهاش رو دستی پیدا کنی. یا این‌که یه‌بار اسمت رو تو یه جعبه‌ی اسم‌دار (متغیر) می‌ذاری، و هرجا لازم شد فقط اسم جعبه رو صدا می‌زنی.

## ۴. دمو زنده: کنتراست (کمتر از ۵ دقیقه) — درد دستی در مقابل ابزار

> این دمو دقیقاً همون الگوی «کار دستی خسته‌کننده → ابزاری که کارو کوتاه می‌کنه» است که برای مفهوم تکرار در PY-00 لازم بود ولی جا افتاده بود. این‌بار برای متغیر درست پیاده می‌شود.

### اجرای اول — بدون متغیر (کار دستی و تکراری، عمداً خسته‌کننده نشان داده می‌شود)
```python
print("سلام، آرش هستم!")
print("آرش امروز ۱۰ سالشه.")
print("تولد آرش رو تبریک بگو!")
```
راوی حین تایپ کردن هر خط، عمداً کند و با غرغر بازیگوشانه می‌گوید: «باز بنویسم آرش... دوباره... بازم...» — هدف این است که تکرار دستی اسم، محسوس و کمی خسته‌کننده حس شود.

سپس یک سؤال می‌پرسد: «حالا اگه اسمش عوض بشه به سارا، باید چندجا رو دستی عوض کنم؟» — سه‌جا را می‌شمارد.

### اجرای دوم — با متغیر (همون نتیجه، یه‌جا تعریف)
```python
name = "آرش"
print("سلام، " + name + " هستم!")
print(name + " امروز ۱۰ سالشه.")
print("تولد " + name + " رو تبریک بگو!")
```
اجرا می‌شود؛ خروجی همان است. سپس راوی فقط خط اول را عوض می‌کند:
```python
name = "سارا"
```
و دوباره اجرا می‌کند — هر سه خط بدون دست‌زدن به بقیه‌ی کد، خودشان عوض می‌شوند.

**نکته‌ی کلیدی راوی:** «دیدی؟ فقط یه‌جا رو عوض کردم، ولی هر سه خط خودشون به‌روز شدن. این جادو نیست — چون هر سه خط داشتن از همون جعبه می‌خوندن.»

> این کنتراست باید واقعاً دوبار در `PythonCodeRunner` اجرا شود؛ حس «صرفه‌جویی در کار» باید محسوس باشد، نه فقط گفته شود.

## ۵. تمرین هدایت‌شده

### هدف تمرین
> **مأموریت: یه جعبه‌ی اسم بساز، یه جعبه‌ی سن بساز، و با استفاده از هر دو یه جمله چاپ کن. بعد مقدار سن رو عوض کن و دوباره چاپ کن.**

نوار مأموریت:
- ⬜ متغیر `name` ساختم
- ⬜ متغیر `age` ساختم
- ⬜ با هر دو یه جمله چاپ کردم
- ⬜ مقدار `age` رو عوض کردم و دوباره چاپ کردم

### گام‌به‌گام
1. `name = "..."` را می‌نویسد.
2. `age = ...` (عدد، بدون گیومه) را می‌نویسد.
3. با `print` یک جمله می‌سازد که از هر دو متغیر استفاده کند.
4. اجرا می‌کند و می‌بیند جمله درست چاپ می‌شود.
5. فقط خط `age = ...` را تغییر می‌دهد و دوباره اجرا می‌کند تا ببیند فقط با تغییر یک خط، جمله‌ی چاپ‌شده هم به‌روز می‌شود.

## ۶. خطا = «مینی نمی‌دونه این جعبه رو کجا بذاره»

| خطای رایج | پیام سیستم مینی |
|---|---|
| استفاده از متغیری که هنوز تعریف نشده (`NameError`) | «مینی دنبال یه جعبه به این اسم گشت ولی پیداش نکرد. مطمئنی قبلش ساختیش؟» |
| غلط تایپی در اسم متغیر (مثلاً `name` جای `nam`) | «مینی یه جعبه با این اسم دقیق پیدا نکرد — شاید حروفش یه‌کم فرق داره؟» |
| فراموشی گیومه دور مقدار متن (`name = آرش`) | «مینی فکر کرد آرش هم اسم یه جعبه‌ی دیگه‌ست، نه یه کلمه — دور کلمه گیومه لازم داره.» |

- محل خط خطا مثل PY-02 هایلایت می‌شود.
- دکمه‌ی «🔁 دوباره امتحان کن» + (رده B) traceback خام قابل‌بازشدن.

## ۷. چالش‌ها

### رده A — «معرفی با دو جعبه»
> با دو متغیر (اسم و یه چیزی که دوست داری) یه معرفی کوتاه بساز.

### رده B — «سه‌تا جعبه، و یه تغییر وسط داستان»
> سه متغیر بساز (اسم، سن، شهر). یه معرفی کامل چاپ کن. بعد مقدار شهر رو عوض کن (انگار جابه‌جا شدی) و دوباره معرفی رو چاپ کن — ببین فقط همون بخش عوض می‌شه.

## ۱۰. یادداشت برای پیاده‌سازی محصول

- این درس اولین‌باریه که مفهوم «تغییر مقدار و مشاهده‌ی اثرش» مطرح می‌شود — پیشنهاد می‌شود مأموریت هر گام (`done/pending`) یک آیتم اضافه‌ی مخصوص همین داشته باشد («مقدار رو عوض کردم و دوباره چاپ کردم»)، چون این خودِ نکته‌ی آموزشی اصلی درس است، نه یک قدم جانبی.
- خطای `NameError` احتمالاً پرتکرارترین خطای این درس خواهد بود؛ در `pythonErrorMessages.ts` باید این پیام با اولویت بالا map شود.
- همین الگوی کنتراست («سه بار تایپ دستی» در مقابل «یه‌بار تعریف، چندبار استفاده») می‌تواند بعداً الگوی مرجع برای بازنویسی دموی «تکرار» در PY-00 هم باشد — چون دقیقاً همون نوع تجربه‌ی «آها» که آنجا کم بود، اینجا درست از آب درآمد.
